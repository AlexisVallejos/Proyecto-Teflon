No se usa FTP, SFTP, usuario Linux ni carpeta FTP publica. El programa de gestion sube imagenes por API HTTP, Vase devuelve una URL estable y esa URL se envia en el producto.

1. Endpoints

Uso Metodo URL
Probar conexion GET https://editor.vase.ar/api/v1/integrations/ping
Subir imagen estable POST https://editor.vase.ar/api/v1/integrations/images/upload
Crear o actualizar productos POST https://editor.vase.ar/api/v1/integrations/products/sync

2. Headers obligatorios

x-api-key: vase_84189d23cb046b4b23a20951767ba5d2cbc5d1386d962cf7
x-tenant-id: aa2e2d94-c7b1-4bc1-93f0-77e5003ddfe7

Para JSON, agregar tambien:

Content-Type: application/json

3. Flujo de prueba recomendado

  1. Probar conexion con /ping.
  2. Subir una imagen local con /images/upload.
  3. Guardar la URL estable devuelta en url o public_url.
  4. Enviar el producto a /products/sync usando esa URL en images.
  5. Revisar el producto en el catalogo del editor.
Usar solo URLs que empiecen con https://uploads.vase.ar/public-files/products-. No usar URLs temporales que empiecen con https://uploads.vase.ar/public/.

4. Paso 1 - Probar conexion

$token = "vase_84189d23cb046b4b23a20951767ba5d2cbc5d1386d962cf7"
$tenant = "aa2e2d94-c7b1-4bc1-93f0-77e5003ddfe7"

curl.exe -X GET "https://editor.vase.ar/api/v1/integrations/ping" `
  -H "x-api-key: $token" `
  -H "x-tenant-id: $tenant"

Respuesta esperada:

{
  "ok": true
}

5. Paso 2 - Subir imagen

Cambiar la ruta por una imagen real de la PC donde corre el programa.

$image = "C:\Gestion\Imagenes\PROD-1001_1.jpg"

$upload = curl.exe -s -X POST "https://editor.vase.ar/api/v1/integrations/images/upload" `
  -H "x-api-key: $token" `
  -H "x-tenant-id: $tenant" `
  -F "file=@$image" | ConvertFrom-Json

$upload
$imageUrl = $upload.url
$imageUrl

Respuesta esperada:

{
  "ok": true,
  "url": "https://uploads.vase.ar/public-files/products-aa2e2d94-c7b1-4bc1-93f0-77e5003ddfe7/archivo.jpg",
  "public_url": "https://uploads.vase.ar/public-files/products-aa2e2d94-c7b1-4bc1-93f0-77e5003ddfe7/archivo.jpg"
}

6. Paso 3 - Sincronizar producto con imagen

$product = @{
  source_system = "sistema-gestion"
  items = @(
    @{
      external_id = "PROD-1001"
      sku = "PROD-1001"
      name = "Producto prueba con imagen"
      description = "Producto creado desde API para prueba"
      short_description = "Prueba API"
      brand = "Marca prueba"
      price_1 = 24990
      price_2 = 21990
      stock = 15
      is_active = $true
      category_path = "Pruebas API > Imagenes"
      images = @(
        @{
          url = $imageUrl
          primary = $true
        }
      )
    }
  )
}

$body = $product | ConvertTo-Json -Depth 10

$headers = @{
  "x-api-key" = $token
  "x-tenant-id" = $tenant
  "Content-Type" = "application/json"
}

Invoke-RestMethod `
  -Method Post `
  -Uri "https://editor.vase.ar/api/v1/integrations/products/sync" `
  -Headers $headers `
  -Body $body

Respuesta esperada:

{
  "ok": true
}

7. Crear otro producto

Para crear otro producto, cambiar external_id y sku. Si se repite el mismo external_id, la API actualiza el producto existente.

$product.items[0].external_id = "PROD-1002"
$product.items[0].sku = "PROD-1002"
$product.items[0].name = "Producto prueba con imagen 2"
$product.items[0].price_1 = 35990
$product.items[0].stock = 8

$body = $product | ConvertTo-Json -Depth 10

Invoke-RestMethod `
  -Method Post `
  -Uri "https://editor.vase.ar/api/v1/integrations/products/sync" `
  -Headers $headers `
  -Body $body

8. Campos principales

Campo Uso
external_id Obligatorio. Identificador estable del producto en el sistema de gestion.
sku Codigo comercial del producto.
name Nombre del producto.
price_1, price_2... Tarifas del producto.
stock Stock disponible. Viaja dentro del producto; no hay endpoint separado de stock.
images Array de imagenes. Cada item puede tener url y primary.
category_path Ruta de categoria recomendada. Ejemplo: Categoria principal > Subcategoria.
Resumen operativo: primero subir imagen, despues mandar producto con la URL estable devuelta. No guardar ni enviar URLs temporales de /public/.
